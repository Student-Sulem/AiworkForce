How it works

Agents propose. People dispose.

Autonomy without oversight is a liability. This platform separates the two explicitly: employees generate, humans decide, and every decision is recorded.

1

Configure an employee

Give each AI employee a system prompt, assign it a language model from OpenRouter, NVIDIA NIM or a local Ollama instance, and attach the MCP tools it is permitted to use.

2

Let it work

The employee calls its model, consults its tools, and produces a draft: a social post, an outreach email, a scored prospect or a strategy insight. Nothing is published.

3

Review and decide

The draft lands in your approval queue. Approve it and it goes live; reject it and you record why. Either way the audit trail keeps the whole history.

Questions

Frequently asked

Can an AI employee publish something on its own?
No. Every runner writes its output as a draft and raises an approval request. The record only becomes live when a person approves it, and that single transition is the one place in the codebase where publication happens.
Which language models are supported?
OpenRouter, NVIDIA NIM and Ollama. Each provider has its own API key, endpoint and model catalogue, and each AI employee is assigned one specific model. If no model is reachable, the employee falls back to a built-in template so a run never fails outright.
Do I need an API key to try it?
No. The model catalogue is seeded locally, and every employee works from built-in templates until you assign it a live model. Add a key when you want real generation.
What exactly does the MCP layer do?
It records and validates each tool server's connection details, tracks the capabilities each one advertises, and controls which employees may use them. This build models the protocol inside the application rather than launching external server processes.
Is there an audit trail?
Yes. Every approval records who decided, when, and why, and a separate audit log keeps the full history including the original submission and any edits made before approval.
