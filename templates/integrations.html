An unconfigured integration is simulated, not broken

Most of these services need an OAuth application and a company account before they will accept a single call, so every connector implements each operation twice: once against the real service, and once as a faithful simulation. Where no credential has been entered, the platform runs the simulation and labels every simulated action as simulated -- in the tool result, in the execution record, in the audit trail and on the screen. Nothing is ever presented as having happened when it did not.

Paste a credential into an integration's Configure dialog and it moves to live with no code change and no restart. If a simulated action must never be mistaken for a real one, set that integration to Live only: it will then fail with an explanation rather than simulate. Switching an integration off does the same -- it stops, rather than quietly becoming a pretend version of itself.
